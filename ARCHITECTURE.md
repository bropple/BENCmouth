# BENCmouth architecture

A formant speech synthesizer in C99. No dynamic allocation, no libm in the core, no I/O
below the host layer.

## The pipeline

```
  "Hello, world."
        |
   [normalize]      numbers, abbreviations, punctuation -> plain words + break marks
        |
   [lookup]         CMUdict exact match ..................... ~90% of running text
        |  miss
   [lts rules]      NRL 7948 letter-to-sound rules ........... the rest
        |
        v
   HH AH0 L OW1 , W ER1 L D .
        |
   [prosody]        durations, stress -> F0 contour, phrase-final lengthening
        |
        v
   timed phoneme stream
        |
   [frames]         phoneme targets -> parameter frames @ 100 Hz, interpolated
        |
        v
   bm_frame stream  (public type - you can inject here)
        |
   [synth]          cascade/parallel formant DSP @ 22050 Hz
        |
        v
   PCM
```

Each arrow is a testable boundary. The two that matter most are `bm_text_to_phonemes()`
(a pure string transform, so front-end bugs are readable instead of audible) and
`bm_render_frame()` (drive the DSP with hand-written frames and no front end at all).

## Layout

```
include/bencmouth.h      the entire public API, freestanding-safe

src/core/                no stdio, no stdlib, no malloc, no libm
  bm_engine.c            public API, lifecycle, storage, the pull loop
  bm_resonator.c         two-pole resonator and antiresonator primitives
  bm_glottis.c           voiced source: pulse shape, open quotient, tilt, flutter
  bm_noise.c             aspiration and frication source (xorshift, not rand())
  bm_synth.c             cascade + parallel topology, the DSP top level
  bm_frames.c            phoneme targets -> interpolated bm_frame stream
  bm_phonemes.c          phoneme inventory + per-phoneme target tables
  bm_text.c              normalization, numbers, abbreviations
  bm_lts.c               NRL letter-to-sound rule matcher
  bm_rules_en.c          GENERATED by tools/mkrules.c - do not hand-edit
  bm_voice.c             presets, parameter setter, throat/mouth blending
  bm_math.c              cos/exp/sqrt/dB polynomial approximations; replaces libm

  bm_prosody.c           (planned) phrase-level F0 and duration
  bm_dict.c              (planned) compiled CMUdict lookup

src/host/                platform glue; embedded targets simply don't build this
  main.c                 the `bm` CLI
  bm_wav.c               RIFF/WAVE writer, float->int16 with soft limiting
  bm_voicefile.c         `key = value` voice file loader/saver
  bm_audio_alsa.c        (planned) live playback

tools/
  mkrules.c              ref/NRL-7948-TRANS.SNO -> src/core/bm_rules_en.c
  level_check.c          per-phoneme loudness audit against a reference vowel
  vowel_demo.c           hand-written frames straight into the DSP
  speak_demo.c           phoneme strings and voice comparison renders
  mkdict.c               (planned) cmudict -> compact compiled table

tests/
  test_resonator.c       filter response, stability, math accuracy
  test_synth.c           formant peaks, periodicity, nasal cancellation
  test_phonemes.c        inventory sanity, frame generator, voice effects
  test_text.c            letter-to-sound, numbers, normalization
  test_voices.c          presets, serialization, the Retro golden reference

voices/                  shareable voice files, checked in
render/                  generated audio, gitignored
ref/                     source material - see ref/README.md before adding anything
```

The `core`/`host` split is the whole portability story. Core has no include of `<stdio.h>`
anywhere; if that ever stops being true, the microcontroller build is what breaks first
and you won't find out until you try it. Worth a grep in CI.

## Design decisions worth defending

**No allocation, anywhere.** A formant synthesizer's state is a fixed set of filter
coefficients and delay lines. There is nothing to allocate. Callers provide a
`bm_engine_storage` and place it wherever they like. The cost is compile-time capacity
limits (`BM_MAX_PHONEMES`, `BM_MAX_TEXT`); the benefit is that the library drops into a
microcontroller, an audio callback, or a WASM module unchanged.

**Pull model, not push.** `bm_read()` renders on demand rather than calling a callback or
filling a buffer you own. Every real audio API — ALSA, CoreAudio, WASAPI, SDL,
AudioWorklet — is "here is a buffer, fill it now, don't block." A pull model satisfies
that directly. A push model would need a ring buffer and probably a thread.

**Cascade *and* parallel branches.** Voiced sound goes through formants in series, which
is physically what the vocal tract does and gets the relative formant amplitudes right for
free. Fricatives and stop bursts need antiresonances that a cascade cannot produce, so they
get a parallel path with per-formant amplitudes. This is the Klatt 1980 topology and it is
the mainstream choice for a reason. (Holmes 1983 argues for pure parallel; it needs more
per-phoneme parameter tuning to sound good, which is the tradeoff.)

**Float first, fixed-point later, behind a typedef.** Getting a formant synth to sound
*right* is hard enough without simultaneously fighting Q15 saturation. `bm_sample` and
`BM_SAMPLE_FLOAT` mark the seam. Be aware the typedef alone won't do it — the DSP inner
loops will need Q-format multiply macros too, so avoid scattering bare `*` through
`bm_synth.c` if you want that port to stay mechanical.

**Voice as plain data.** `bm_voice` is POD with no pointers into mutable state, so it lives
in `.rodata`, embeds in firmware, and serializes. It's also the file you edit to give
BENCmouth its character, which is the part users will actually care about.

## The Retro contract

**Every naturalness improvement must be a voice parameter whose "off" setting reproduces
the older, cruder behaviour.** A feature that cannot be switched off is a feature that has
silently taken the retro voice away.

`BENCmouth Retro` is the original voice. It is pinned, and `tests/test_voices.c` holds it
to that with a golden reference — sample count, peak, RMS, zero-crossing rate, and an
eight-slice envelope, so a failure tells you *what* drifted (level, timing, or brightness)
rather than merely that something did. When a legitimate DSP change moves those numbers,
re-measure and say so in the commit; updating them quietly is how a pinned voice stops
being pinned.

`coarticulation` is the pattern to copy. Real articulators undershoot their targets, and
adding that makes speech markedly more natural — so it arrived as a parameter defaulting to
`0.0`, and Retro leaves it there. `render/coart-off.wav` and `render/coart-on.wav` are the
same utterance either side of that switch.

## On sounding like BENCmouth and not like a generic formant synth

S.A.M.'s charm is inseparable from its crudeness — three formants, brutal 6502 compromises,
and a buzzy glottal source. It's tempting to reproduce that by building something equally
crude. Don't. Build the capable synthesizer and then *dial it toward* the retro end using
`bm_voice`: drop `f0_flutter` and `f0_range` toward zero for the monotone robot, raise
`tilt` down for buzz, widen bandwidths for that plastic quality. You can always make a good
synthesizer sound deliberately cheap. You cannot make a cheap one sound good.

## Build order

1. `bm_resonator.c` + `bm_math.c` — get a stable filter and prove it with a sweep. **Done.**
2. `bm_glottis.c` + `bm_noise.c` — sources you can listen to in isolation.
3. `bm_synth.c` + `bm_render_frame()` — hand-write a few `bm_frame`s and make a vowel.
   **This is the first real milestone. Done** — see `tools/vowel_demo.c`. A sustained /a/
   that sounds like /a/ means the DSP is right, and everything above it is bookkeeping.
4. `bm_phonemes.c` + `bm_frames.c` — targets and interpolation, so phoneme strings work.
5. `bm_prosody.c` — durations and F0, which is what makes it stop sounding like a list.
6. `bm_lts.c` + `bm_rules_en.c` + `bm_dict.c` — the text front end last, since
   `bm_speak_phonemes()` already works by then and the front end is independently testable.

Front end last is deliberate: it's the least interesting part, it's the part most likely to
be thrown away and rewritten, and building it first means a long stretch with nothing to
listen to.
